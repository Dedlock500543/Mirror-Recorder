# Mirror Recorder

GitHub: <https://github.com/Dedlock500543/Mirror-Recorder>

English version: [README_EN.md](README_EN.md)

История изменений: [CHANGELOG.md](CHANGELOG.md)

Клиентский мод для **Minecraft 1.12.2 / Forge 14.23.5.2864**, который записывает ввод игрока
(движение, повороты, клики, прыжки, чат, слоты хотбара) и затем воспроизводит его.
Мод не использует собственную симуляцию физики — он повторяет именно нажатия,
поэтому воспроизведение остаётся согласованным с игровой механикой.

> Мод **client-side only**. Устанавливать на сервер не нужно и нельзя.

---

## Требования

| Компонент | Версия |
|---|---|
| Minecraft | 1.12.2 |
| Minecraft Forge | 14.23.5.2864 или новее в ветке 1.12.2 |
| Java (для игры) | Java 8 |
| Java (для сборки из исходников) | **JDK 8** — ForgeGradle 3 не работает на JDK 9+ |
| Baritone | необязательно, подключается рефлексией |

---

## Установка

1. Установите Minecraft Forge для 1.12.2.
2. Положите `Mirror-Recorder-1.12.2-1.0.1.jar` в папку `mods` вашего игрового каталога.
3. Запустите игру.

Пути ниже указаны относительно **вашего** игрового каталога (`.minecraft` или каталог инстанса
в MultiMC / Prism / CurseForge и т. п.). Мод сам определяет их через Forge и никуда больше не пишет.

| Что | Где |
|---|---|
| Конфиг | `config/mirror_recorder.cfg` |
| Записи | `mirror_recorder/slot_N.nbt` (`.bak` — резервная копия, `.tmp` — временный файл) |
| Экспорт | `mirror_recorder/exports/*.mrr` |
| Корзина | `mirror_recorder/trash/` (до 20 последних удалённых записей) |
| Журнал диагностики | `logs/mirror-debug.log` (только если диагностика включена) |

## Управление

Клавиши **по умолчанию не назначены**, чтобы не конфликтовать с другими модами.
Назначьте их в `Настройки → Управление → Mirror Recorder`, либо пользуйтесь командами.

| Команда | Действие |
|---|---|
| `/mirror gui` | открыть главное окно мода |
| `/mirror record <слот>` | начать запись |
| `/mirror play <слот>` | воспроизвести один раз |
| `/mirror loop <слот>` | воспроизводить циклично |
| `/mirror limit <слот> <N>` | ограничить число циклов (`0` — без лимита) |
| `/mirror stop` | остановить всё |
| `/mirror list` | список занятых слотов |
| `/mirror name <слот> <имя>` | переименовать запись |
| `/mirror delete <слот>` | удалить запись (уходит в корзину) |
| `/mirror marker <слот> [текст]` | задать описание записи |

Доступно 100 слотов, максимум 72 000 кадров на слот (1 час при 20 TPS).

## Возможности

- Запись и воспроизведение ввода без изменения физики.
- Циклическое воспроизведение с лимитом циклов и пропуском задержки между циклами.
- Скорость воспроизведения 0.25×–4×. Нажатия из пропущенных кадров воспроизводятся в том же порядке, поворот берётся из последнего кадра такта. Стабилизация маршрута работает только на скорости 1.0×.
- Ограниченная стабилизация маршрута — только через ввод, без телепортов.
- Автовозврат в точку старта (опционально через Baritone, если он установлен).
- Визуализация маршрута и маркер точки старта (точка / кольцо / луч), цвет настраивается.
- HUD статуса; в окнах мода он перетаскивается как **Shift + перетаскивание мышью** — без Shift клик всегда достаётся кнопкам под ним.
- Импорт/экспорт записей в `.mrr`, дублирование слотов, корзина.
- Языки интерфейса: русский, английский, украинский, немецкий, польский. По умолчанию язык следует языку игры (`auto`), вручную переключается в `Настройки → Интерфейс → Язык`. Названия клавиш в «Управлении» переводит сама игра по своему языку, а не по языку мода; название самого раздела всегда `Mirror Recorder` и не переводится.
- Остановка при получении урона (настраивается) и при ручном вводе движения — W, A, S, D или пробел.

## Сборка из исходников

Нужен **JDK 8**. Сборка проверяет это сама и падает с понятным сообщением на JDK 9+.

```bat
set "JAVA_HOME=<путь-к-вашему-JDK-8>"
gradlew.bat --no-daemon build
```

```sh
export JAVA_HOME=<path-to-your-jdk8>
./gradlew --no-daemon build
```

Результат: `build/libs/Mirror-Recorder-1.12.2-1.0.1.jar` (уже реобфусцированный, `jar.finalizedBy('reobfJar')`).

Запуск клиента для проверки: `gradlew runClient` (рабочий каталог `run/`).
Сводка окружения сборки: `gradlew modInfo`.

При изменении версии обновите её в трёх местах:

1. `build.gradle` → `version`
2. `src/main/resources/mcmod.info` → `"version"`
3. `src/main/java/com/mirror/recorder/MirrorRecorder.java` → `VERSION`

## Важно знать

- Запись переживает переход между мирами (лобби → катка): всё пишется в один файл, повтор на границе ждёт загрузки нового мира и продолжает. Важно: переход при повторе должен случиться по-настоящему — записанный заход в портал, клик по меню или команда.
- В записи попадают и клавиши внутри окон: выброс и раскладка предметов цифрами, закрытие окна клавишей, текст на наковальне и табличке. Комбинации с Ctrl в текстовых полях (вставка из буфера) не повторяются — это ограничение.
- Записи, сделанные в этой версии, запоминают открытый интерфейс: при повторе окно торговца или сундука закрывается там же, где закрылось при записи. Старые записи тоже закрывают окно, но по записанным кликам — точность около полусекунды.
- Если клавиши мода в «Управлении» были испорчены прошлыми версиями, выставьте их один раз — дальше они будут сохраняться.
- Воспроизведение чата отправляет **настоящие** сообщения и команды на сервер.
  На публичных серверах учитывайте правила — автоматизация ввода может быть запрещена.
- Запись чата по умолчанию **выключена**, чтобы в файлы записей не попали личные
  сообщения и пароли. Включается в `Настройки → Запись`.
- Baritone не является зависимостью: если его нет, автовозврат работает в упрощённом
  локальном режиме выравнивания.
- Чат и команды из **импортированных** записей не отправляются вообще: чужой `.mrr`
  не сможет написать в чат или выполнить команду от вашего имени. При первом таком кадре
  мод пишет об этом в чат. Свои записи работают как раньше.
- Клики в игровых окнах (сундуки, верстаки) повторяются по записанному положению
  курсора и только в окне того же типа. Содержимое контейнера мод не проверяет — если предметы
  лежат иначе, чем при записи, клик попадёт по другому слоту.
- Повреждённая запись теперь открывается частично: битые кадры пропускаются,
  остальные воспроизводятся, а в `logs/` остаётся запись о том, сколько кадров потеряно.
